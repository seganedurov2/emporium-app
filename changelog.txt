[VERSION 0.4.2 - PREVIOUS RELEASE] "INPUT: Pointer Map, Leaner App.tsx"

  MEZZANINE MAP
  * The region map now pans with mouse, pen and finger and zooms with a pinch.
    The old mouse-only handlers are replaced by pointer events; one pointer
    pans, two pinch (zoom follows the change in distance between them, the pan
    follows their midpoint so the map stays under the fingers), a third finger
    is ignored until one of the first two lifts.
  * Touch on the map no longer scrolls or zooms the page (touch-action: none).
  * Pinch zoom is clamped to the same 8..200 tile range as the wheel and the
    +/- buttons. src/mapGestures.ts is the React-free gesture math.

  ARCHITECTURE
  * The weekly cycle left App.tsx: advanceCampaignWeek (src/campaignWeek.ts)
    turns the campaign state plus the numbers App owns (raid queue, hospital
    staff, records) into the next state, the week's logs, the event of the
    week, the achievement toast, the ending and the records to store. The handler in App now only feeds it and writes the result back.
  * The pure meta-progress half of that cycle lives in
    src/campaignGoalAdvance.ts (lifetime stats, campaign goal, leaderboard).
  * Slot persistence moved to src/campaignPersistence.ts: same slot keys, same
    legacy emporium_save_06 fallback for slot 1, same plain or encrypted body
    and the same audit entries, so existing saves load unchanged.
  * The exhaustion/health labels and the off-duty recovery constant moved to
    src/campaignWeekConstants.ts; App imports them.

  BACKGROUND
  * The weekly cycle keeps its order and arithmetic; the save format is
    untouched (no new fields, no changed ones). The 0.4.1 city-economy weekly
    report is still written exactly as before.

[VERSION 0.4.1 - PREVIOUS RELEASE] "CITY: Municipal Economy on the Weekly Cycle"

  CITY ECONOMY
  * New engine src/cityEconomyEngine.ts (pure, React-free): every week the city plan
    pays municipal tax on employed residents and filled jobs, a park subsidy, with
    income scaled by building condition; it bills upkeep for finished buildings and
    unemployment benefits for residents with no local job. Unfinished construction
    neither pays nor bills. A healthy town (>=60% jobs filled, positive surplus)
    breaks ground on new lots funded from the surplus; a poor or unstaffed town
    stagnates and says so in the log.
  * advanceWeek applies the report once per week, writes it to lastWeeklyReport
    (revenue.city / expenses.city, including new construction) and into the
    campaign log. Finance tab, history chart and chief-doctor report include the
    city line; the city-plan panel shows last week's income, expenses, surplus and
    any new construction.
  * Save: new versioned cityEconomy block, with round-trip, corrupt and pre-0.4.1
    migration tests; the city plan produced by town growth is written back.

  MULTIPLAYER
  * The hub is optional again: with no VITE_WS_URL the client no longer dials
    ws://localhost:5175/ws from deployed pages (it used to retry every 2 s and
    flood the console with WebSocket errors). src/multiplayerConfig.ts resolves
    the URL once: absolute VITE_WS_URL or relative /ws against the page origin
    (ws/wss by page scheme); localhost-only default for development.
  * The hook probes the hub once before connecting and reconnects with a backoff
    (2 s -> 30 s); the panel reports "не настроен" when no hub is configured.
  * npm run dev:full starts Vite and the hub together; npm run dev:hub runs the
    hub alone.

  CAMPAIGN SCRIPT
  * "Мезонин открыт" now records the first hub opening (cityHubOpenedAt) instead of
    reading the current map tab, so the act-3 objective stays satisfied once reached.
    Saves that already used the hub are backfilled with their current week.

--- CHANGES SINCE 0.3.6 ---
* Save state:
    - New mezzanine block in the campaign save: selected region, selected city,
      view mode, zoom (gridSize), pan offset and city-builder seed.
    - Migration on load: pre-0.3.7 saves load with an empty view instead of
      failing; corrupted blocks are repaired (zoom clamped to 8..200,
      coordinates clamped, unusable city dropped, seeds floored to >= 1).
    - The hub reports its view through onViewChange; App stores it in
      gameState so saves, slot switching and autosave pick it up.
    - src/mezzanineViewState.ts holds the schema and normalizer (React-free).
* Performance:
    - Wheel zoom is coalesced with requestAnimationFrame: several wheel ticks
      inside one frame produce a single render instead of one per event.
    - drawBlock moved to src/mezzanineRender.ts with a seeded PRNG for grass
      strokes - panning no longer re-rolls the texture every frame.
    - City window geometry (cityVisibleRect) is clamped as a pair, so a city far
      off its region collapses to an empty window instead of negative bounds.
    - Visible-area clipping: a 64x64 region at tile 48 used to fill an
      8k x 4k canvas on every render, freezing the hub on the second click;
      off-screen rows/columns are now culled (847k -> ~780x420 px of drawing).
    - Keymap and pause overlays moved to a fixed layer; as absolute children of
      the 100vh hub box they were hidden behind the app header.
    - Map constants (regions, cities, terrain generator) are memoized and the
      pan offset is read from a ref, so dragging does not rebuild the render
      callback.
* Keyboard:
    - 1..7 quick-switch regions, C toggle city, R/M region/city map,
      B city plan, K 3D map, + / - zoom, Tab sections, ? keymap, Esc menu.
    - One keydown listener owns Escape: 3D -> keymap -> city plan -> menu, so a
      single press never opens and closes the same overlay.
    - Hotkeys are ignored while typing in inputs/selects; the keymap overlay
      renders straight from the resolver table, so help cannot drift.
* Fixes (mezzanine map):
    - The hub showed a flat green field because the city window collapsed to
      zero width for Kalinkovichi (cell -21, west of the Gomel reference); the
      window now slides inside the map and keeps its full radius.
    - Region and city maps share one isometric projection centred on the box;
      before, x was placed by column centre and y by row offset.
    - The canvas was sized from parentElement.clientHeight, which grew with the
      content (1494px canvas in a 720px window); it is now sized from the hub
      box via ResizeObserver and clipped to the visible area.
    - The region diamond is fitted to the box with a 10% margin instead of
      overflowing it; wheel zoom still zooms in.
    - Map tiles no longer draw under the side panels and the bottom toolbar;
      the drawing area is padded to the free region.
    - The bottom toolbar moved inside the hub (it sat below the fold), the
      right-hand controls became one column (they overlapped), the sections
      button joined the left column, and the mini map gained a compact mode.
* Tech debt:
    - Removed HiringTab.new.tsx and HiringTab_temp.tsx (~370 lines of dead
      copies); HiringTab_new2.tsx renamed to HiringTab.tsx.
    - tools/qa-mezzanine.mjs + npm run qa:mezzanine: browser smoke that waits
      for real screens and asserts on DOM geometry, not shared page text.
    - Version strings in the title screen, header badge and footer were stuck
      on v0.3.0; now read v0.3.7 from the same release.
* Tests:
    - New suites: mezzanineViewState (save schema), mezzanineShortcuts
      (keymap resolver), mezzanineRender (terrain colours, window geometry),
      plus 4 mezzanine migration cases in saveState.test.ts.
