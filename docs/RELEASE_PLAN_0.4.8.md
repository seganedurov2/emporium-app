# Release Plan 0.4.8 — "CORE: Stability & UX Polish"

Кодовое название: **CORE: Stability & UX Polish**

## Цель релиза
Закрепить результаты релизов 0.4.5–0.4.7, закрыть накопленные технические долги, повысить надёжность, производительность и UX приложения.

## Фокус
- Надёжность и обработка ошибок
- UX-полировка (скелетоны, состояния загрузки)
- Завершение работ по i18n и теме
- Расширение unit-тестов
- Улучшение инфраструктуры CI/CD

## Задачи

### 1. Надёжность и обработка ошибок
- [x] **Error Boundaries** — добавить React Error Boundaries для ключевых вкладок и экранов. Обеспечить понятный fallback UI вместо краша всего приложения
- [x] **Единый обработчик ошибок** — централизовать обработку сетевых/расчётных ошибок с информативными уведомлениями
- [x] **Защита критичных расчётов** — добавить проверки и безопасные дефолты в модули экономики/мезонина

### 2. UX и производительность
- [x] **Скелетоны загрузки** — добавить индикаторы/скелетоны для тяжёлых вкладок (во избежание "пустого" экрана при первом открытии)
- [x] **Ленивая загрузка** — перевести тяжёлые вкладки на динамический импорт где уместно
- [x] **Оптимизация рендеров** — проработать узкие места в производительности крупных списков/таблиц
- [x] **Полировка анимаций и состояний** — привести состояния кнопок/форм к единообразию

### 3. Тема, стилизация и i18n
- [x] **CSS-переменные** — привести оставшиеся жёстко прописанные цвета к использованию `bg-background`/`text-foreground` и CSS-переменных из `@theme/[data-theme]`
- [x] **Завершение i18n** — закрыть оставшиеся захардкоженные строки на русском языке, довести покрытие `ru/en` для пользовательских текстов
- [x] **Проверка контрастности** — верифицировать читаемость в светлой и тёмной темах
- [x] **Синхронизация переводов** — проверить отсутствие ключей с пустыми значениями

### 4. Тестирование
- [x] **Экономика и неделя** — расширить unit-тесты расчётов экономики, цикла недели и связанных утилит
- [x] **Мезонин/City Builder** — покрыть тестами ключевые функции планирования города
- [x] **Хуки и утилиты** — добавить тесты для общих хуков/хелперов
- [x] **Интеграционные smoke-тесты** — при возможности расширить существующие smoke-проверки

### 5. Инфраструктура и DevEx
- [x] **CI/CD** — доработать `.github/workflows/ci.yml` (кэширование зависимостей, понятные шаги, ускорение прогона)
- [x] **Линт/типы** — привести кодовую базу к чистому проходу `npm run lint` и `tsc -b`
- [x] **Сборка** — убедиться в успешном прохождении `npm run build` (включая `add-spa-404.mjs` и `check-chunks.mjs`)
- [x] **Документация** — актуализировать `README.md` при необходимости (скрипты, запуск, тесты)

## Критерии приёмки
- [x] `npm run lint` — без ошибок
- [x] `npm run test` — все тесты проходят
- [x] `npm run build` — успешная сборка, артефакты в `dist/`
- [x] Сохранения остаются совместимыми (обратная совместимость со старыми слотами не нарушена)
- [x] В ключевых вкладках отсутствуют необработанные краши
- [x] Нет новых захардкоженных пользовательских строк там, где используется i18n
- [x] Стили в основных экранах используют CSS-переменные темы

## Релизные действия
- [x] Обновить версию в `package.json` до `0.4.8`
- [x] Создать/обновить релизные заметки (changelog.txt)
- [x] Прогнать полный цикл проверок (`lint`, `test`, `build`)
- [ ] Собрать дистрибутив
- [ ] Деплой (с учётом текущего процесса)

## Примечания
- **Сохранения**: не менять формат сохранений. Любые изменения структуры должны сохранять `migrateCampaignState` и обратную совместимость.
- **App.tsx**: при рефакторинге не трогать модули `*Engine.ts` — выносить только React-обвязку.
- **Порядок релизов**: фокус на стабилизации, без масштабного архитектурного рефакторинга.
- **Тема**: при правках стилей приоритет — использование CSS-переменных, а не жёстких цветовых классов.
