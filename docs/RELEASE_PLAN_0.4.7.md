# Release Plan 0.4.7 — "CORE: Stability & UX Polish"

Кодовое название: **CORE: Stability & UX Polish**

## Цель релиза
Закрепить результаты релизов 0.4.5–0.4.6, закрыть накопленные технические долги, повысить надёжность, производительность и UX приложения.

## Фокус
- Надёжность и обработка ошибок
- UX-полировка (скелетоны, состояния загрузки)
- Завершение работ по i18n и теме
- Расширение unit-тестов
- Улучшение инфраструктуры CI/CD

## Задачи

### 1. Надёжность и обработка ошибок
- [ ] **Error Boundaries** — добавить React Error Boundaries для ключевых вкладок и экранов. Обеспечить понятный fallback UI вместо краша всего приложения
- [ ] **Единый обработчик ошибок** — централизовать обработку сетевых/расчётных ошибок с информативными уведомлениями
- [ ] **Защита критичных расчётов** — добавить проверки и безопасные дефолты в модули экономики/мезонина

### 2. UX и производительность
- [ ] **Скелетоны загрузки** — добавить индикаторы/скелетоны для тяжёлых вкладок (во избежание "пустого" экрана при первом открытии)
- [ ] **Ленивая загрузка** — перевести тяжёлые вкладки на динамический импорт где уместно
- [ ] **Оптимизация рендеров** — проработать узкие места в производительности крупных списков/таблиц
- [ ] **Полировка анимаций и состояний** — привести состояния кнопок/форм к единообразию

### 3. Тема, стилизация и i18n
- [ ] **CSS-переменные** — привести оставшиеся жёстко прописанные цвета к использованию `bg-background`/`text-foreground` и CSS-переменных из `@theme/[data-theme]`
- [ ] **Завершение i18n** — закрыть оставшиеся захардкоженные строки на русском языке, довести покрытие `ru/en` для пользовательских текстов
- [ ] **Проверка контрастности** — верифицировать читаемость в светлой и тёмной темах
- [ ] **Синхронизация переводов** — проверить отсутствие ключей с пустыми значениями

### 4. Тестирование
- [ ] **Экономика и неделя** — расширить unit-тесты расчётов экономики, цикла недели и связанных утилит
- [ ] **Мезонин/City Builder** — покрыть тестами ключевые функции планирования города
- [ ] **Хуки и утилиты** — добавить тесты для общих хуков/хелперов
- [ ] **Интеграционные smoke-тесты** — при возможности расширить существующие smoke-проверки

### 5. Инфраструктура и DevEx
- [ ] **CI/CD** — доработать `.github/workflows/ci.yml` (кэширование зависимостей, понятные шаги, ускорение прогона)
- [ ] **Линт/типы** — привести кодовую базу к чистому проходу `npm run lint` и `tsc -b`
- [ ] **Сборка** — убедиться в успешном прохождении `npm run build` (включая `add-spa-404.mjs` и `check-chunks.mjs`)
- [ ] **Документация** — актуализировать `README.md` при необходимости (скрипты, запуск, тесты)

## Критерии приёмки
- [ ] `npm run lint` — без ошибок
- [ ] `npm run test` — все тесты проходят
- [ ] `npm run build` — успешная сборка, артефакты в `dist/`
- [ ] Сохранения остаются совместимыми (обратная совместимость со старыми слотами не нарушена)
- [ ] В ключевых вкладках отсутствуют необработанные краши
- [ ] Нет новых захардкоженных пользовательских строк там, где используется i18n
- [ ] Стили в основных экранах используют CSS-переменные темы

## Порядок работ
1. **Анализ** — пройтись по TODO/FIXME, баг-репортам и пунктам из плана
2. **Надёжность** — Error Boundaries + обработка ошибок (приоритет)
3. **UX** — скелетоны, ленивая загрузка
4. **Тема/i18n** — доводка
5. **Тесты** — расширение покрытия
6. **CI/инфраструктура** — правки воркфлоу
7. **Финальная проверка** — линт, тесты, билд, smoke

## Релизные действия
- [ ] Обновить версию в `package.json` до `0.4.7`
- [ ] Создать/обновить релизные заметки
- [ ] Прогнать полный цикл проверок (`lint`, `test`, `build`)
- [ ] Собрать дистрибутив
- [ ] Деплой (с учётом текущего процесса)

## Примечания
- **Сохранения**: не менять формат сохранений. Любые изменения структуры должны сохранять `migrateCampaignState` и обратную совместимость.
- **App.tsx**: при рефакторинге не трогать модули `*Engine.ts` — выносить только React-обвязку.
- **Порядок релизов**: фокус на стабилизации, без масштабного архитектурного рефакторинга.
- **Тема**: при правках стилей приоритет — использование CSS-переменных, а не жёстких цветовых классов.
