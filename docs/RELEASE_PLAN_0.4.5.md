# Emporium 0.4.5 — i18n & Theme: «Локализация и тема»

**Status:** Draft for review
**Baseline:** `v0.4.4` (Mezzanine Journal + stability gate)
**Intent:** Закрыть оставшиеся UX-разрывы из `project.md`: ввести лёгкий слой локализации (русский по умолчанию, английский вторым), переключатель тёмной/светлой темы и базовое покрытие unit-тестами расчётов экономики. Без изменений формата сохранений.

## Текущее состояние (baseline facts)

Уже в кодовой базе (не регрессировать):
- Тема жёстко тёмная; переключатель отсутствует (`gaps.theme_toggle`).
- Весь текст жёстко на русском; система локализации отсутствует (`gaps.i18n`).
- Инфраструктура unit-тестов (vitest) и тесты экономики/расчёта мезонина не выявлены (`gaps.unit_tests`).
- Глобальные стили body используют жёсткие классы; по решению `theme.css_variable_usage` нужно использовать `bg-background`/`text-foreground` из CSS-переменных.
- `0.4.4` добавил error boundaries, loading skeletons, save migration tests, CI/CD — не ломать.

## Область работ

### P0 — Переключатель темы (save-format neutral)

1. Вынести жёсткую тёмную палитру в CSS-переменные (`--bg`, `--fg`, `--surface`, `--accent`) под `[data-theme="dark"]`/`[data-theme="light"]` в `src/index.css` (или эквиваленте).
2. Создать `src/theme.ts` (React-free): `getTheme()`, `setTheme()`, `applyTheme()`; хранение в `localStorage` под ключом `emporium_theme`. Не добавлять поле в `ManagedCampaignState`.
3. Создать `ThemeProvider`/хук `useTheme()` и компонент `ThemeToggle` в настройках; переключение без перезагрузки страницы.
4. Заменить жёсткие `bg-slate-950`/`text-slate-100` на `bg-background`/`text-foreground` в корневом layout и ключевых экранах.
5. Избежать FOUC: инлайн-скрипт в `index.html` применяет тему до гидратации.

### P0 — Локализация (i18n)

1. Создать `src/i18n/`:
   - `types.ts` — тип `Locale = 'ru' | 'en'`, тип словаря.
   - `ru.ts`, `en.ts` — словари ключей.
   - `index.ts` — `t(key, params?)`, `getLocale()`, `setLocale()`, хранение в `localStorage` (`emporium_locale`), fallback на `ru`.
2. React-обвязка: хук `useI18n()` + контекст `I18nProvider`; компонент `LanguageSwitcher` в настройках.
3. Локализовать в первую очередь: навигация (`appNavigation.ts` метки), настройки, заголовки вкладок Мезонина, сообщения об ошибках/загрузке. Остальной UI — поэтапно, ключи добавляются по мере touched-экранов.
4. Не смешивать локализацию с игровыми движками (`*Engine.ts`) — только React-обвязка и константы меток.

### P1 — Unit-тесты экономики

1. Настроить Vitest (если отсутствует): `vitest.config.ts`, скрипт `test` в `package.json` (если нет).
2. Покрыть чистые функции:
   - `src/campaignWeek.ts` — `advanceCampaignWeek` (порядок недели, арифметика).
   - `src/campaignGoalAdvance.ts` — метапрогресс, цели, лидерборд.
   - `src/campaignPersistence.ts` — round-trip сохранения, миграция слотов.
   - Экономика города (weekly report) — расчёт доходов/расходов.
3. Тесты round-trip сохранений остаются зелёными; без изменений `saveState`.

### P1 — Качество (quality gates)

1. Тесты (Vitest, pure-first):
   - `theme`: `getTheme`/`setTheme`/`applyTheme` round-trip; невалидное значение → default.
   - `i18n`: `t()` возвращает ключ при отсутствии перевода; переключение локали; fallback.
   - Экономика/неделя: как выше.
2. Команды верификации:
   - `npm test`
   - `npm run lint`
   - `npx tsc -b`
   - `npm run build`
3. Ручной QA:
   - Переключение темы на всех основных экранах; отсутствие FOUC.
   - Переключение языка; fallback на ru при неизвестной локали.
   - Мобильный viewport; отсутствие консольных ошибок.
   - Отсутствие влияния на загрузку/сохранение кампании.

### P2 — Отложено (вне scope 0.4.5)

- Полная локализация всего UI (оставшиеся экраны).
- Дополнительные темы (high-contrast, кастомные акценты).
- Игровые эффекты темы/языка (бонусы, экономика).
- Удалённая синхронизация словарей / CMS.
